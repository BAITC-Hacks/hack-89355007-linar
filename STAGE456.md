# Этапы 4–6: документы и контрольные требования

Два каталога `company_before` и `company_after` содержат по шесть настоящих файлов DOCX/XLSX. Все документы относятся к синтетической учебной компании. В них намеренно смоделированы потеря ведения реестра рисков ИБ, пересечение мониторинга ИБ и отсутствие ответственного за реагирование в должностной инструкции после реорганизации.

`regulatory/catalog.json` содержит пять категорий источников. Внешние источники даны только как справочные ссылки; вымышленные отраслевой критерий и внутренние документы явно помечены. `regulatory/requirements.json` содержит четыре атомарных учебных критерия с ID, источником, пунктом, категорией, областью применения и проверяемым условием. Проверяющий алгоритм в `lib/regulatory.js` ищет подтверждение только в заданных файлах и возвращает выдержки с пунктами. Отсутствие подтверждения — сигнал экспертной проверки, а не установленное нарушение.

Проверка: `npm ci`, `npm test`, `npm start`. Откройте `http://localhost:3000`, перейдите в «Документы», нажмите «Анализировать 12 учебных файлов DOCX и XLSX». Доступны также `GET /api/sample-analysis`, `GET /api/regulatory`, `GET /api/requirements`. В Windows PowerShell используйте `npm.cmd ci`, `npm.cmd test`, `npm.cmd start`.

Для воспроизведения файлов разработчиком: `scripts/build_documents.py` создаёт DOCX, `scripts/build_workbooks.mjs` создаёт XLSX, `scripts/normalize_workbooks.py` совместит экспортированные XLSX с текущим импортером ExcelJS. Генератор XLSX требует установленного `@oai/artifact-tool`; готовые файлы уже включены в репозиторий, поэтому для запуска приложения генерация не нужна.
