# OrgLens

Локальный прототип анализа организационной структуры и функций. Русскоязычный интерфейс: обзор, изменения подразделений, матрица функций, риски, исходные фрагменты, аналитическое заключение и экспорт Markdown / печать PDF.

## Запуск

Требуется Node.js 22 или новее.

```sh
npm install
npm start
```

Откройте http://localhost:3000. Сервер слушает только `127.0.0.1`. Порт задаётся переменной окружения `PORT`. Для демонстрации и локальных правил ключи не нужны. Для семантического ИИ-анализа подключите OpenAI и/или NVIDIA по инструкции ниже. Для воспроизводимой установки после клонирования с lock-файлом используйте `npm ci`.

```sh
npm test
```

## OpenAI API и NVIDIA API

1. Скопируйте `.env.example` в `.env` в корне проекта (`Copy-Item .env.example .env` в PowerShell).
2. Заполните `OPENAI_API_KEY` и `NVIDIA_API_KEY` своими ключами. Можно подключить один провайдер. Секреты вводите в локальный файл, не в чат и не в исходники. `.env` исключён из Git и не раздаётся HTTP-сервером.
3. При необходимости задайте `OPENAI_MODEL` и `NVIDIA_MODEL`. Примеры по умолчанию: `gpt-4.1-mini` и `meta/llama-3.3-70b-instruct`. Доступность модели и квота зависят от аккаунта; пример NVIDIA следует дополнительно оценить на русскоязычном контрольном наборе.
4. Перезапустите `npm start`. Панель «Семантическая проверка» покажет, для каких провайдеров задан ключ. Это наличие настройки, а не проверка баланса или валидности ключа.
5. Загрузите документы или откройте демо, выберите OpenAI, NVIDIA либо оба и нажмите «Запустить ИИ-анализ».

OpenAI вызывается через Responses API (`store:false`, строгий JSON Schema). NVIDIA вызывается через OpenAI-совместимый Chat Completions API. Кредиты и токены используются на стороне соответствующих аккаунтов; ключ сам по себе не добавляет баланс. Приложение показывает расход токенов завершённого запроса, но не остаток кредита. Подписка/лимиты приложения Codex не используются этим сервером в качестве API-ключа.

Внешним сервисам передаются распознанные функции, названия подразделений, имена документов и подтверждающие цитаты. Сырые бинарные файлы и весь текст документа не отправляются. Использование внешних API происходит только по нажатию кнопки; открытие демо и загрузка файлов сами по себе не тратят API-кредиты. В режиме обоих провайдеров выполняются два независимых запроса, результаты доступны отдельно. Расхождения матрицы сопоставления выделяются; наборы рисков не объединяются в якобы согласованный вывод. Можно скачать оба анализа с источниками в JSON или активное заключение в Markdown.

Модель возвращает только ID существующих функций. Сервер проверяет полноту матрицы, направление «до → после», типы отклонений и соответствие подразделений. Названия документов, номера пунктов и цитаты восстанавливаются из исходных данных, а не из сгенерированного текста. Эти проверки обеспечивают прослеживаемость, но не доказывают семантическую правильность выводов. Структура подразделений по-прежнему определяется локальным парсером; ИИ анализирует только распознанные функции.

Ограничения одного ИИ-запроса: 60 функций и 60 000 символов сериализованного контекста. При превышении комплект нужно разделить; незаметного усечения нет. Таймаут по умолчанию 90 секунд (`AI_TIMEOUT_MS`, максимум 180 секунд). Автоматических повторных платных запросов нет. Ответы с обрывом, некорректным JSON или выдуманными ID не применяются. При ошибке одного провайдера сохраняется ответ другого и отображается ошибка; локальный результат доступен отдельно. HTTP 401 означает отклонённый ключ, 403 — отсутствие доступа, 429 — ограничение частоты или квоты/кредитов.

Интеграционные тесты API используют подставные ответы и не расходуют кредиты. Для проверки реального подключения нужны собственные ключи и запуск ИИ-анализа в интерфейсе.

Если ключ OpenAI задан, он выбирается по умолчанию; режим обоих провайдеров включается вручную. Отдельный риск с неподходящей группировкой подразделений исключается с видимым предупреждением, а корректная матрица и остальные риски сохраняются. Выдуманные ID или неполная матрица по-прежнему отклоняют весь ответ.

Официальная документация: [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [NVIDIA Chat Completions](https://docs.api.nvidia.com/nim/reference/meta-llama-3_3-70b-instruct-infer).

## Демонстрация

При открытии загружается встроенный контрольный комплект (8 текстовых примеров). Имена с расширением DOCX служат названиями демонстрационных источников; это не реальные бинарные Word-файлы. Исходные тексты доступны в «Документах» и в `lib/demo.js`.

Ожидаемые результаты:

- Финансовый департамент → Департамент экономики и финансов; Управление закупок → Департамент закупок.
- Юридический отдел сохранён; Департамент внутреннего контроля создан.
- Ведение реестра финансовых рисков не найдено после (п. 1.4 исходного положения).
- Мониторинг договорных обязательств присутствует в закупках (п. 2.2) и внутреннем контроле (п. 4.1).
- Проведение платежей и контроль платежей закреплены в одном подразделении (пп. 1.2–1.3).

Для проверки полного сценария загрузите файлы из `examples/before/` в комплект «до» и `examples/after/` в комплект «после». Это тот же контрольный набор в формате TXT.

Кнопка «Источники» открывает название документа, пункт, дословный фрагмент и полный извлечённый текст. «Скачать заключение» экспортирует Markdown с матрицей сопоставления, рекомендациями и исходными текстами. В разделе заключения доступна печать в PDF средствами браузера.

## Свои документы

Нажмите «Новый анализ», добавьте файлы в комплекты «до» и «после». Поддерживаются DOCX, PDF с текстовым слоем, XLSX, TXT/MD (UTF-8). До 15 МБ на файл, 30 МБ суммарно, 30 файлов. Старые DOC и XLS нужно преобразовать в DOCX и XLSX. Сканы без текстового слоя требуют предварительного OCR.

Прототип использует **структурированный вход**, а не универсальное понимание произвольных документов. Текст должен содержать заголовки подразделений и нумерованные функции:

```text
Подразделение: Финансовый департамент
1.1. Формирование и согласование годового бюджета компании.
1.2. Ведение реестра финансовых рисков компании.
```

Для явного подтверждения преобразования в комплекте «после»:

```text
Реорганизация: Финансовый департамент → Департамент экономики и финансов
Подразделение: Департамент экономики и финансов
1.1. Формирование и согласование годового бюджета компании.
```

В Excel размещайте заголовок подразделения в одной строке, затем номер и функцию в соседних столбцах. В Word нумерация должна быть частью текста: автоматические номера списков могут не сохраниться при извлечении. Переносы внутри PDF могут нарушить распознавание. Всегда проверяйте извлечённый текст и количество функций в «Документах». Нераспознанные документы сопровождаются предупреждениями.

## Архитектура

```text
Браузер (HTML/CSS/JS)
    → POST /api/analyze (имя, период, base64)
    → Node.js HTTP-сервер
    → mammoth / pdf-parse / exceljs: извлечение текста
    → analyzer: подразделения, функции, источники
    → сопоставление / правила риска
    → JSON → интерфейс / заключение Markdown
```

- `server.js` — HTTP и адаптеры документов; файлы обрабатываются в памяти.
- `lib/analyzer.js` — чистая функция анализа, не зависит от интерфейса.
- `lib/ai.js` — адаптеры OpenAI/NVIDIA, валидация ID и сравнение ответов.
- `public/ai-ui.js` — выбор API, запуск и переключение между результатами.
- `lib/demo.js` — воспроизводимый контрольный комплект.
- `public/` — интерфейс без сборки и фреймворков.
- `test/` — контрольные проверки результатов и прослеживаемости.

Тесты также запускают отдельный сервер и проверяют загрузку настоящих DOCX, XLSX и PDF, передачу кириллицы, отклонение повреждённых файлов и неполных комплектов. ExcelJS использует исправленную `uuid` 11 через npm override; совместимость проверяется тестом чтения XLSX.

Каждая функция сохраняет ID документа, пункт и точную цитату. Подразделения связываются по точному названию или явной записи о реорганизации. Функции сравниваются по пересечению нормализованных значимых слов (упрощённое удаление окончаний): 72% для сопоставления, 82% для возможного дублирования между подразделениями. Конфликт обязанностей — ограниченное правило исполнения и контроля платежей/закупок в одном подразделении. Оценка совпадения не является вероятностью.

## Границы прототипа

Локальный режим использует эвристики; ИИ-режим добавляет семантическое сопоставление через OpenAI/NVIDIA. Прототип не обеспечивает извлечение графических оргструктур, OCR, нормативную проверку и бенчмаркинг. «Не найдено» означает отсутствие совпадения в распознанном комплекте, а не подтверждённую потерю функции. Сигналы дублирования и конфликтов требуют экспертной проверки. Ссылка ведёт к извлечённому пункту, а не к странице оригинального PDF.

Документы не сохраняются сервером на диск. В ИИ-режиме указанные выше данные передаются выбранным провайдерам и обрабатываются по условиям этих сервисов; `store:false` не является обещанием нулевого хранения у провайдера. После обновления страницы снова открывается демо. Шрифт загружается из Google Fonts (без содержимого документов); без сети используется системный шрифт. Нет авторизации и промышленной защиты парсеров: сервер предназначен для локальной демонстрации с доверенными документами. Для эксплуатации нужны изоляция обработки, хранение с контролем доступа, OCR, более надёжное извлечение и оценка качества на реальных документах.
