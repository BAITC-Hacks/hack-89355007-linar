# Этапы 7–12: извлечение, база знаний, аудит и заключение

## Быстрый запуск

```powershell
npm.cmd ci
npm.cmd test
npm.cmd start
```

Откройте `http://localhost:3000`. В разделе «Документы» доступны учебный сценарий разделения Департамента ИБ и загрузка собственных комплектов «до/после». Для двух обезличенных редакций Положения о внутреннем аудите загрузите редакцию 8 в «До», редакцию 9 в «После», затем нажмите «Начать анализ». В результатах откройте «Документы» или «Риски»: у кандидатов на изменение пунктов показаны обе цитаты с номерами пунктов и именами файлов. В «Рисках» выберите для наблюдений решение «Подтверждено» или «Ложное срабатывание». Кнопка «Скачать заключение по подтверждённым выводам» находится в разделах «Документы» и «Аналитическое заключение».

Используются реальные файлы, загруженные через браузер; две переданные отдельно обезличенные редакции в публичный репозиторий не добавлены. Для работы с ними загрузите их в интерфейсе. Сервис привязан к `127.0.0.1`. Без PostgreSQL загруженные данные и решения существуют лишь до перезапуска сервера.

## Данные и ограничения

- `lib/document-parser.js` извлекает фрагменты DOCX/PDF/XLSX и хранит имя документа, пункт, страницу PDF или лист/ячейку XLSX. У DOCX физическая страница без отдельной верстки достоверно не устанавливается: поле `page = null`.
- `lib/clause-diff.js` сравнивает нумерованные пункты двух редакций, сохраняет обе цитаты. Изменение формулировки само по себе не является нарушением; аудитор подтверждает значимость.
- `lib/extraction-agent.js` выделяет функции, должности, полномочия и ответственность локальными правилами; при явно включённом режиме ИИ и заданном `OPENAI_API_KEY` использует Responses API и проверяет все ID источников. Передача реальных документов во внешний сервис происходит только при включении ИИ.
- `lib/scenario.js` содержит деление ИБ на Security Operations и Risk Department с пропущенной функцией ведения реестра рисков.
- `lib/audit.js` сопоставляет функции и утверждённые внутренние критерии, собирает отклонения и формирует Markdown только из подтверждённых аудитором наблюдений. Справочные ссылки на внешние акты не интерпретируются как доказательство соблюдения закона.
- `lib/knowledge.js` выполняет локальный поиск по 64-мерным детерминированным векторам слов. Это быстрый демонстрационный поиск; полноценные семантические embeddings пока используются только в отдельной существующей функции ИИ-поиска.

## PostgreSQL и pgvector

С Docker Desktop выполните `docker compose up -d`. В PowerShell до запуска Node задайте:

```powershell
$env:DATABASE_URL = "postgresql://orglens:orglens_demo_local@127.0.0.1:5433/orglens"
npm.cmd start
```

При первом аудите сервер применит `db/schema.sql`: структуры подразделений, сотрудников, функций, требований и исходных фрагментов, включая индекс pgvector. Данные аудита и решения сохраняются в PostgreSQL. Проверьте режим через `GET /api/audit/storage`. Это локальные демонстрационные реквизиты; для иных установок используйте собственные параметры.

API: `POST /api/audit` принимает `{files:[{name,period,data}], ai:false}` или `{scenario:true}`; `POST /api/audit/search` принимает `{auditId,query}`; `POST /api/audit/report` принимает `{auditId,decisions:{findingId:{status,comment}}}`.
